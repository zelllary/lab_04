# Лабораторная работа №4

## Что реализовано

- Обход вложенной структуры рекурсивно и итеративно.
- Сортировка вставками.
- Быстрая сортировка.
- Очередь на основе списка.

Также написаны генераторы пяти наборов: случайного, отсортированного, обратного, почти отсортированного и с дубликатами.

## Установка и запуск

Нужен Python 3.14 или выше. Команды для PowerShell из папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e . --group dev
python -m algorithms
```

Программа выводит примеры работы функций и запускает замеры времени сортировок.

Проверки:

```powershell
python -m pytest
ruff check
mypy .
```

## Особенности работы

Обход поддерживает вложенные списки, кортежи и множества с целыми числами и строками. Рекурсивная функция вызывает сама себя, итеративная использует стек. Порядок элементов множества не гарантируется. Неизвестный тип вызывает `TypeError`.

Глубина рекурсии ограничена Python. Лимит можно узнать через `sys.getrecursionlimit()`. При его превышении возникает `RecursionError`. Для большой глубины можно использовать итеративный обход. Циклические структуры не поддерживаются.

Сортировки работают с `int` и `float`, возвращают новый список и не меняют исходный. Поддерживаются пустой список, отрицательные числа и повторы. Если передан не список или выполняется сравнение несовместимых элементов, возникает `TypeError`. Вставки сдвигают большие элементы вправо, а быстрая сортировка делит участок на элементы меньше, равные и больше опорного.

Дополнительное задание: стабильность сортировки вставками проверяется отдельным тестом. Равные по значению элементы сохраняют свой порядок. Например, `[2.0, 1, 2, 1.0]` превращается в `[1, 1.0, 2.0, 2]`. В тесте проверяются и значения, и типы, чтобы отличать равные `int` и `float`.

Очередь работает по принципу FIFO: кто добавлен первым, тот извлекается первым. Есть методы `queue_add`, `queue_pop`, `queue_peek`, а также `len` и `bool`. Индекс `head` указывает на начало очереди. Когда обработана половина списка, эта часть удаляется. Просмотр и извлечение из пустой очереди вызывают `IndexError`.

Генераторы создают списки с целыми и вещественными числами. Вещественные значения имеют один знак после запятой. Одинаковые размер и `seed` дают одинаковый случайный набор. При отрицательном размере возникает `ValueError`, при нуле возвращается `[]`.

## Сложность

`n` — размер списка, а для обхода — общее число обрабатываемых элементов и контейнеров. Память указана с учётом результата, без исходных данных.

| Алгоритм | Время | Дополнительная память |
| --- | --- | --- |
| Рекурсивный обход | До `O(n²)` при большой вложенности | `O(n)` |
| Итеративный обход | `O(n)` | `O(n)` |
| Вставки | Лучшее `O(n)`, среднее и худшее `O(n²)` | `O(n)` |
| Быстрая сортировка | В среднем `O(n log n)`, худшее `O(n²)` | `O(n)` |
| Генераторы | `O(n)`, для почти отсортированного — в среднем | `O(n)` |

Рекурсивный обход может несколько раз копировать готовые элементы через `extend()` на разных уровнях вложенности. Поэтому в худшем случае время квадратичное. Сортировкам нужна дополнительная память для копии списка.

Добавление и извлечение из очереди занимают `O(1)` в среднем по длинной серии операций. Отдельное расширение или очистка списка может занять `O(n)`. Просмотр, длина и проверка пустоты — `O(1)`. Вся очередь занимает `O(n)` памяти.

## Замеры времени

Обе сортировки проверяются на пяти видах наборов размером **1000, 3000 и 10 000**. Для каждого случая выполняется пять запусков с `seed = 67`. Всего получается 150 замеров.

Время измеряется через `perf_counter()`. Генерация и подготовка новой копии выполняются до включения таймера. Измеряется вызов сортировки, включая её внутреннее копирование.

Дополнительное задание: программа автоматически создаёт таблицу со средним временем повторов и его ростом относительно предыдущего размера для той же сортировки и набора. Результаты проведённых измерений и выводы приведены ниже.

Результаты обычного запуска приведены ниже. В таблице среднее время пяти повторов в секундах.

| Сортировка | Набор | 1 000 | 3 000 | 10 000 |
| --- | --- | ---: | ---: | ---: |
| Вставки | Случайный | 0.029585 | 0.301182 | 3.114512 |
| Вставки | Отсортированный | 0.000149 | 0.000458 | 0.001636 |
| Вставки | Обратный | 0.054964 | 0.521181 | 5.963262 |
| Вставки | Почти отсортированный | 0.000868 | 0.007875 | 0.085582 |
| Вставки | С дубликатами | 0.024451 | 0.207485 | 2.274178 |
| Быстрая | Случайный | 0.002118 | 0.007360 | 0.030272 |
| Быстрая | Отсортированный | 0.001791 | 0.005817 | 0.022922 |
| Быстрая | Обратный | 0.002136 | 0.006395 | 0.022438 |
| Быстрая | Почти отсортированный | 0.001741 | 0.006278 | 0.022478 |
| Быстрая | С дубликатами | 0.000298 | 0.001304 | 0.003549 |

При увеличении случайного списка с 1 000 до 10 000 элементов время вставок выросло примерно в 105 раз, а быстрой сортировки — в 14 раз. Это согласуется с `O(n²)` для вставок и средним `O(n log n)` для быстрой сортировки.

На отсортированном входе вставки работают быстрее, потому что сдвиги не нужны. На дубликатах быстрой сортировке помогает отдельная обработка элементов, равных опорному.

### Большие размеры

Отдельно выполнены замеры быстрой сортировки на размерах из указания преподавателя: 100 000, 1 000 000 и 10 000 000. Для каждого набора выполнено пять повторов с `seed = 67`, способ измерения тот же. Среднее время в секундах:

| Набор | 100 000 | 1 000 000 | 10 000 000 |
| --- | ---: | ---: | ---: |
| Случайный | 0.279453 | 3.900061 | 50.270254 |
| Отсортированный | 0.189267 | 2.164154 | 25.837161 |
| Обратный | 0.183738 | 2.162033 | 24.780997 |
| Почти отсортированный | 0.184313 | 2.213208 | 25.427331 |
| С дубликатами | 0.025843 | 0.219386 | 2.288196 |

При увеличении случайного входа в 10 раз время быстрой сортировки выросло примерно в 14 и 13 раз. Результаты согласуются со средним `O(n log n)`.

Для вставок все пять видов входа проверены на размере 40 000. Среднее время пяти повторов в секундах:

| Набор | 40 000 |
| --- | ---: |
| Случайный | 34.113528 |
| Отсортированный | 0.003923 |
| Обратный | 58.280750 |
| Почти отсортированный | 0.770111 |
| С дубликатами | 23.422813 |

Дополнительно случайный список из 50 000 элементов проверен пять раз: среднее время — **53.628720 с**. По сравнению с 40 000 размер вырос в 1,25 раза, а время — в 1,57 раза. Это близко к квадрату увеличения размера: `1,25² = 1,5625`.

Уже отсортированный вход проверен и на больших размерах:

| Размер | Вставки, среднее время пяти повторов, с |
| ---: | ---: |
| 100 000 | 0.010247 |
| 1 000 000 | 0.097850 |
| 10 000 000 | 1.016253 |

На отсортированном входе сдвигов нет, поэтому вставки работают за `O(n)`. Для случайного и обратного входа нужны многочисленные сдвиги, поэтому размеры для них выбраны меньше.

Все большие замеры в сумме заняли около **26 минут**, включая генерацию и подготовку данных. Всего выполнено 120 дополнительных замеров. В таблицах выше приведено среднее время пяти повторов для каждого случая.

Большие расчёты выполнены отдельно для каждой сортировки. В обычном запуске `__main__.py` оставлены размеры 1 000, 3 000 и 10 000, чтобы каждый запуск программы не занимал столько времени.

Случайные вещественные числа округляются до одного знака после запятой. Даже при одинаковом `seed` время может отличаться из-за нагрузки на компьютер. Размеры для обычного запуска задаются в `__main__.py`. Тесты дополнительных заданий находятся в `tests/test_adidtionally.py`.
